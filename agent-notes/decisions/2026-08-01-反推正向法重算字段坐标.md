# 决策：反推-正向法重算字段坐标 + 文字角度归一化

**日期**：2026-08-01
**关联计划**：原理图重叠修复（P0-a）
**状态**：已实施

## 背景

旋转/镜像原理图符号后，其属性字段（Reference/Value 等）的 `(at)` 坐标停留在旋转前的绝对位置，导致文字与符号体重叠。此前的 `update_symbol_rotation_mirror` 只改 `(at x y rot)` 的旋转分量和 `(mirror ...)` token，不动 property 的 `(at)`。

## 候选方案

1. **直接旋转现有字段坐标**：把字段当前位置绕符号原点旋转。问题：无法区分"用户已手动移动过的字段"与"在 lib 默认位置的字段"，且 lib 默认偏移在镜像下本就该翻转到对侧，直接旋转会得到错误象限。
2. **反推 lib offset + 正向变换重算**（采用）：从 `lib_symbols` 读出每个 property 的 lib 默认 `(at dx dy ang)`，用与 `pin_world_xy` 完全相同的正向变换（Y-flip → rotate(-R) → mirror → translate）重新计算字段绝对坐标。这样字段始终跟随 body 的当前姿态，与 KiCad eeschema 自身的放置语义一致。

## 决策

采用方案 2。新增两个静态方法于 `wire_dragger.py`：

- `get_lib_property_positions(sch_data, lib_id)`：从 `lib_symbols` 读取 top-level（unit-0/共享）property 的 `(dx, dy, text_angle)`，遇到子 symbol 定义（`symbol "X_1_1"`）即停止——unit-specific property 不在此处理。
- `_recompute_symbol_field_positions(item, sym_x, sym_y, rot, mirror_x, mirror_y, lib_props)`：对每个 placed property，跳过 `(do_not_autoplace yes)`，用 `pin_world_xy` 重算位置。

`update_symbol_rotation_mirror` 在改完 `(at)`/`(mirror)` 后调用上述方法重算所有 property 字段。

## 文字角度归一化（keep-upright）

KiCad eeschema 对水平文字只允许 0°、对垂直文字只允许 90°（180° 折回 0°，270° 折回 90°），即"keep-upright"约定。重算时：

```
new_pa = (lib_text_angle + rotation) % 360
if new_pa == 180: new_pa = 0
elif new_pa == 270: new_pa = 90
```

否则会出现 180°/270° 文字，KiCad 会在下次保存时改写，造成不必要的 diff。

## 镜像放置翻转 dx（R2）

`create_component_instance._prop_at` 此前只对 lib 偏移做 `_rotate_offset`，未处理 `mirror_y`。修复：`mirror_y` 时对旋转后的 `rdx` 取负（`(mirror y)` 否定 screen-X，与 `pin_world_xy` 一致），否则镜像实例的字段落到 body 错误的一侧。

## 限制 / 后续

- unit-specific property（如多单元 opamp 的单元属性）不在 top-level，本方法不处理；目前多单元符号的字段仍依赖 autoplace 兜底。
- `do_not_autoplace` 字段被跳过（用户锁定），但 autoplace 工具层面的 `auto` 三态保护（检测字段是否仍在 lib 默认位置）见 P1-c/后续。
